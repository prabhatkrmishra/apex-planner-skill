# Visual and Interaction Planning

For UI, mobile, desktop, design-system, or user-workflow changes, plan observable behavior rather than only components.

Cover when relevant:
- information hierarchy and state transitions;
- empty/loading/error/offline/permission states;
- keyboard, pointer, touch, screen-reader and focus behavior;
- responsive/layout constraints;
- visual regression risks;
- localization, text expansion, right-to-left behavior;
- design-system reuse and token ownership;
- analytics/events tied to product outcomes.

If visual evidence is available through the host, inspect it before finalizing a UI plan. Do not invent screenshots or claim visual validation that was not performed.
